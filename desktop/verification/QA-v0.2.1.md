# 0.2.1 自定义规则验证

日期：2026-11-11，Windows 本机，.NET SDK 10.0.403，未修改的 Mihomo 1.19.33。使用独立数据目录、命名管道和 19097 / 19098 端口，保留正在运行的 0.2.0、Windscribe WireGuard 连接、系统代理和 helper。验证对象是新增规则功能及其恢复路径；0.2.0 的断线恢复、安装后浏览器与退出重开验收见[原有记录](QA-v0.2.0.md)，不视为本版重复验收。

## 自动化与原生界面

Release 测试 124/124 通过，覆盖域名和完整网址规范化、Unicode 域名、重复与非法输入、两种 VPN 的策略映射、规则优先级、草稿隔离、导出与迁移基线保留、损坏规则文件、离线保存与取消、待恢复标记及控制接口回读。独立审查后的最后一次取消检查位置调整，相关规则测试 32/32 通过。

原生 WPF 共渲染八个场景，包括 1440×960 与 960×720 自定义规则页面。使用独立数据目录实际操作了粘贴网址、选择国内直连/拦截、添加、上移、停用、保存、删除草稿和放弃修改。列表、选中行与保存提示符合操作结果，小窗口可滚动到保存区；未保存列表不会修改已提交文件。

## 真实内核隔离验证

| 检查 | 观察结果 |
|---|---|
| 三种策略 | 同一 HTTPS 测试域名设为 REJECT 后连接失败；ChinaDirect 的实际出口与现有 helper 一致；VPN 的实际出口与基线 VPN 一致，两个出口不同 |
| 首次匹配与范围 | 精确 VPN 规则在前时请求可达；子域名 REJECT 规则上移后请求被拦截 |
| 停用、删除、重启 | 停用后恢复基线匹配；删除全部后规则总数回到基线；重启独立内核后仍使用已保存规则 |
| 迁移基线 | 自定义规则独立保存，多次准备配置与接口重绑不会叠加；迁移快照字节保持不变 |
| 保存取消 | 保存开始后取消，已提交 JSON、配置与实际内核规则恢复，确认后清除待恢复标记 |
| 文件提交失败 | 独占锁定测试规则文件使最终提交失败，内核已应用的候选规则被回滚，原文件保留 |
| 中断恢复 | 模拟候选已在内核运行但尚未提交，恢复流程重启身份确认的自有内核，回读上次已保存规则后清除标记 |
| 覆盖检测域名 | 对 Cloudflare 和百度设置 REJECT，检测改用替代 trace 与指定出站；替代 trace 不可用时仅确认 VPN 出站可达，并明确保留实际出口未验证 |
| 恢复状态回归 | 新服务实例通过活动代理记录的只读副本显示实际出口未验证，不沿用已退出进程的成功假设；此项没有切换实际 VPN |
| 组件占用回归 | 独占锁定隔离组件副本的 geosite.dat，保存失败保留恢复标记；恢复前校验失败时旧核心 PID 和规则继续服务，解锁后完成恢复 |
| 本机状态保留 | 默认与有效 Windows 代理、原安装设置与运行配置哈希、桌面端/helper/主内核/VPN 进程保持不变 |

首次隔离脚本把“替代 trace 必须成功”写成断言，该断言失败；其前面的路由和回退检查通过。按功能约定改为验证“成功比对或明确未验证状态”后，探针与全删恢复的 12 项定向检查通过。独立审查发现的 URL 路径字符误拒、重开后状态误报和组件校验失败前停止旧核心均已局部修复；另有 9 项定向回归通过。停止旧核心前还保留取消检查，未新增周期外网探测或通用恢复状态机。

## 构建、证据与边界

0.2.1 本地测试构建已通过安装 EXE 和便携 ZIP 完整性检查，应用版本 0.2.1 / 文件版本 0.2.1.0，主内核、helper、规则库和附件 SHA-256 核对通过。正式发布从干净提交重建，发布标签须与 `build-info.json` 的提交相同，且 `workingTreeModified=false`；重新核对归档内容及远程附件校验值后发布。

本机证据保存在忽略的 `out/`：`custom-rule-validation/results.json` 记录首次检查中已通过项，`probe-results.json` 记录定向探针检查，`review-results.json` 记录审查修复回归；`custom-rules-ui/` 为八个原生场景，`desktop-v0.2.1/` 为构建产物。发布核验记录放在 `release-v0.2.1/`。原始运行配置、测试规则、代理记录和诊断不作为附件上传。

本轮没有安装替换日常使用的 0.2.0，也未切换 VPN 节点或协议。尚未覆盖 0.2.1 安装后的联网验收、全新机器安装/卸载、Windows 重启登录、Mullvad 动态复测和其他 Windscribe 协议。Mullvad 只有生成配置及控制接口自动化覆盖。规则控制新建连接，已有浏览器连接可能需重新建立；DNS 策略保持原样，规则保存成功不等于网站已访问成功。范围限于遵循系统代理的 HTTP/HTTPS/TCP 流量，不扩展为 UDP、TUN、IPv6 或整机防泄漏保证。
