# 分流助手桌面端

Windows 10/11 x64 的 WPF 桌面预览版。主内核、规则库和直连 helper 随安装包提供，助手统一准备配置、启动组件、管理 Windows 代理和恢复 Windscribe 连接。无需安装 Clash Verge，无需下载 helper 或填写路径。自包含发布，无需另装 .NET。

当前版本为 **0.2.4（桌面预览版）**，修复后台维护造成的周期性界面闪动。详见[更新说明](releases/v0.2.4.md)与[验证范围](verification/QA-v0.2.4.md)。

## 安装与首次设置

从 [v0.2.4 发布页](https://github.com/CainDez/splithelper/releases/tag/v0.2.4) 下载 `SplitHelper-Setup-0.2.4-win-x64.exe`，默认安装到当前用户的 `%LOCALAPPDATA%\Programs\SplitHelper`。便携包 `SplitHelper-0.2.4-win-x64.zip` 需完整解压并放在固定目录。两个包都包含完整组件，可用发布页的 `checksums.sha256` 核对下载内容。

1. 在官方 Mullvad 或 Windscribe 客户端完成登录、选择节点。账号始终由官方客户端管理。
2. 打开“设置 → 连接向导”。Mullvad 点击“配置 Mullvad 分流排除”；Windscribe 按指引启用 **Exclusive / 排除模式**，通过“打开组件位置”将内置 mullvad-direct-helper.exe 加入排除列表，然后勾选确认。分流助手和主内核保留在 VPN 内。
3. Windscribe 使用 **IKEv2 或 WireGuard**。在 Preferences / 设置 → Connection / 连接 → **Proxy Gateway / 代理网关**关闭旧网关，无需填写网关地址、端口和密码。其他设备若仍通过该网关共享 VPN，可为它们保留开启；助手不会使用它。保持 VPN 连接及 helper 排除项。助手保留当前节点和协议；未连接时调用官方客户端连接，再识别实际 VPN 接口。
4. 点击“一键启用”。助手准备独立配置与规则，启动组件，验证国内与海外出口，然后接管默认及活动 IKEv2 连接的代理。WireGuard 使用默认连接代理。
5. 在“自动启动”按需选择登录启动、自动启用分流及关闭时留在托盘，保存即可。启用期间自动恢复 Windscribe 和自身主内核，接口变化后重载配置；退出时还原代理。

Windows 系统代理由助手自动开启、检测和还原，不要在启用分流后手动关闭。Clash Verge 的系统代理、PAC、代理守卫应关闭，Clash Verge 可以退出，无需与助手一起自启动。Windscribe 的“代理网关”、VPN 主连接和 Windows 系统代理是三个不同的设置。

## 从 0.2.x 更新

1. 在当前助手中“停止并还原代理”，再从托盘完全退出。无需先卸载；保留 `%LOCALAPPDATA%\SplitHelper`，其中包含偏好、迁移规则和已有的 `custom-rules.json`。
2. 运行 0.2.4 安装包覆盖原目录。便携版需先完全退出，再完整替换程序文件，保留固定目录。原路径下的 helper 排除项可继续使用。更换程序目录时，在 VPN 客户端重新排除新路径的 helper。
3. 打开助手，确认底部版本为 0.2.4。原有自动启动偏好继续有效。未自动启用时点击“一键启用”。Windows 代理仍由助手管理，Windscribe 无需重新开启代理网关。
4. 在“设置 → 自定义规则”添加异常网站的域名，选择出口并保存，再重新打开网页验证。停用或删除自定义规则后，新连接会重新按剩余规则匹配。

如果 0.2.1 提示仍有 VPN 代理引用主内核，且还原记录已经丢失，先在 Windows 中关闭 `Windscribe IKEv2` 连接上指向助手本地端口的手动代理，再从托盘退出旧版并更新。

## 从 0.1.x 升级

1. 在旧助手中“停止并还原代理”，再从托盘完全退出。保留旧的 Clash 配置和 `%LOCALAPPDATA%\SplitHelper` 数据，不必先卸载旧版。
2. 关闭 Clash Verge 的系统代理、PAC、代理守卫并退出 Clash Verge，然后运行 0.2.4 安装包覆盖原目录。便携版也需先完全退出，保持原目录中的完整组件布局。
3. 打开新版，确认版本为 0.2.4。原路径安装通常可复用 helper 排除。更换安装或便携目录后，在 VPN 中重新添加新路径的 helper。
4. Windscribe 按上述方式关闭不再使用的代理网关，保留 VPN 连接。通过向导“一键启用”，确认各项检查通过。
5. 按需保存登录启动、自动启用和托盘偏好。使用桌面版后，不再运行旧的独立 `Start-Helper` / `Enable-Autostart` 脚本；如果曾手动设置旧 helper 自启动，应停用已确认的旧项，避免重复进程占用端口。

首次迁移只读取当前确认属于助手的 Clash 有效规则，保存独立快照，之后不再依赖 Clash。未找到可确认的旧规则时使用随包通用模板；需要保留私人规则时，在删除旧配置前核对迁移结果。规则顺序保留，仅去掉旧网关方案的 Windscribe 进程直连例外，并将网关策略替换为绑定 VPN 接口的出口。无法安全迁移的外部规则集或未知策略会明确报错，不会自动丢弃它们。

## 日常使用与验收

| 操作 | 预期结果 |
|---|---|
| 点击“一键启用”或启用自动启动后打开助手 | 显示“分流已启用”；内置组件、代理归属、VPN 检查通过 |
| 打开国内网站和 B 站视频 | 国内流量使用 helper / ChinaDirect，本地宽带出口 |
| 打开海外网站并运行助手链路检测 | 海外请求走所选官方 VPN，国内与海外出口检查通过 |
| 点击“停止并还原代理”或从托盘退出 | 还原接管前代理，安全停止自有组件；VPN 客户端继续按自身设置运行 |
| 勾选自动启用、保存偏好，再完全退出并重新打开 | 无需再次点击启用，自动恢复分流 |

“关闭窗口时保留在系统托盘”启用后，点击窗口右上角关闭只隐藏窗口；完全退出请使用托盘菜单。登录自启动需在 Windows 启动设置中保持启用。一次重新打开测试不等于已经完成重启 Windows 的登录测试。

B 站首页可访问不代表视频流已正确分流。诊断视频问题时应核对实际 `bilivideo.com` / `bilivideo.cn` 连接的 `ChinaDirect` 路径；0.2.0 安装后已有 Chrome 1080p 视频流的实测记录，见[既有验收](verification/QA-v0.2.0.md)。自定义规则的验证范围见 [0.2.1 QA](verification/QA-v0.2.1.md)。

仅接管遵循系统代理的 HTTP/HTTPS/TCP 流量。TUN 和 IPv6 保持关闭。VPN 断线保护针对规则选中 VPN 出口的代理请求，不是整台电脑的防火墙。UDP、绕过系统代理的应用及其他 Windscribe 协议不在本次验收范围内。

## GeoSite 和 GeoIP 自动更新

启用分流后，助手在后台检查 MetaCubeX 发布的 `geosite.dat` 和 `country.mmdb`。检查成功后每 24 小时再检查一次，失败后每 30 分钟重试。随包数据用于首次启动或补齐缺失文件，下载后的数据库保存在运行目录，重启时继续使用。可以在“诊断”查看上次成功检查时间。更新地理数据库时，已保存的自定义规则和基础规则顺序保持不变。

## 自定义规则

在“设置 → 自定义规则”点击“添加规则”，填写网站域名或粘贴完整的 HTTP/HTTPS 网址，选择“国内直连”“VPN”或“拦截”，再点击“保存并应用”。程序从网址中提取域名，默认同时匹配其子域名。国内直连经被 VPN 排除的 helper，VPN 使用当前选择的 Windscribe 或 Mullvad 出口。

自定义规则优先于基础规则，从列表顶部向下匹配。选中规则可以编辑、启停、删除或调整优先顺序。分流运行中会热重载并回读核对，未启用时保存到本机，下次启用生效。

例如可把 `bilibili.com` 和 `bilivideo.com`、`bilivideo.cn` 分别设为包含子域名的“国内直连”。网站的视频、图片和登录接口可能使用不同域名，单独修改首页域名不一定覆盖所有资源。按实际异常资源逐项添加，避免过宽的规则。

规则控制**新建连接**的出口，DNS 沿用当前解析策略。保存后刷新或重新打开网页；若浏览器仍复用旧连接，可重新启动浏览器。正常热重载不修改 VPN 选择或 Windows 代理；重载结果无法确认时，助手可能短暂重启自己的主内核，恢复上次已保存规则。

自定义规则保存在 `%LOCALAPPDATA%\SplitHelper\custom-rules.json`，与原有迁移快照分开。重启、协议切换与组件恢复都使用已提交规则，删除自定义规则会恢复原有规则的匹配结果。保存失败或取消不会提交新规则；未确认恢复时会保留待恢复记录并提示，后台继续处理。需要备份时只复制自己的规则文件，不要将代理还原记录迁移到另一台电脑。

如果规则影响助手的固定健康检查网站，检测会使用替代路径；无法完成实际出口比对时会明确显示“实际出口未验证”，不能把该提示当作所选网站已测试成功。网站的最终访问效果仍应在浏览器里验证。

## 停止、更新与卸载

停止或退出会逐连接还原接管前的代理。默认连接与 IKEv2 拨号连接各自保存独立的 DPAPI 备份；0.1.x 旧记录只代表默认连接，不会被当作拨号连接备份。其他软件改动的代理会保留，不自动抢回。

停止前检查所有默认、拨号及当前有效代理；仍有代理引用主内核时保留它。原有 Clash 代理仍依赖 helper 时保留 helper。更新和卸载要求组件可安全停止，无法还原时中止操作并说明原因。旧 Clash 配置仅在卸载旧版管理设置时清理，仍需先退出 Clash GUI；其他订阅保持不变。

本机数据和备份在卸载后保留，详见 [隐私说明](../PRIVACY.md)。

## 构建和验证

使用 .NET 10 SDK、Windows x64、NSIS 3.11。Directory.Build.props 将应用版本设为 0.2.3，文件及程序集版本设为 0.2.3.0。

~~~powershell
# 固定主内核、helper、规则库；校验 SHA256；准备许可证及对应源码
.\desktop\packaging\Prepare-Helper.ps1

dotnet test .\desktop\SplitHelper.Tests\SplitHelper.Tests.csproj -c Release
dotnet run --project .\desktop\tools\AssetBuilder -c Release -- ui-capture "$PWD\out\native-ui-captures"

# 自包含程序、NSIS 安装包、便携 ZIP、SHA256
.\desktop\packaging\Build-Package.ps1
~~~

脚本优先使用仓库 .tools/dotnet/dotnet.exe，也可传入 -Dotnet。构建下载可添加 -Proxy http://127.0.0.1:端口，不改变系统代理。build-info.json 同时记录基础提交和工作树是否有修改，避免把本地未提交构建误标为某个提交的原样产物。

使用 SplitHelper.exe --safe-mode --data-dir <隔离目录> 检查界面：禁用系统及网络变更命令，不写真实客户端配置。原生布局工具也使用独立数据目录。

发布前在干净的已提交工作树运行打包，核对 `build-info.json` 的 `commit` 与发布标签一致、`workingTreeModified=false`。发布附件仅包含程序包、校验文件和第三方源码归档。验证记录见 [0.2.4 QA](verification/QA-v0.2.4.md)，版本变化见[更新说明](releases/v0.2.4.md)。安装包未签名，本版保持预览版。

## 组件和来源

- .NET 10 / WPF，YamlDotNet 18.1.0，MahApps.Metro.IconPacks 6.2.1 / Phosphor Icons。
- 未修改的 Mihomo v1.19.33 Windows amd64 compatible，以两个独立子进程运行。主内核使用独立命名管道；helper 固定监听 127.0.0.1:18997。
- 主内核本地代理自动选择空闲端口，默认从 17897 开始。只监听回环地址，不启用外部 HTTP 控制器。
- 随包 MetaCubeX 数据固定到发布提交，启动时校验安装目录下的文件。后台更新写入用户的运行目录。数据来源、版权和许可证位于 licenses/rule-data/，Mihomo 许可证及对应源码 ZIP 位于 licenses/。
- 原有脚本版模板继续保留；桌面独立配置包含自身 DNS 路径，无需订阅级 JS 扩展。
