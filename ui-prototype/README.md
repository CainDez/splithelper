# 分流助手交互原型

用户选择的第 3 张设计位于 `design/reference.png`。原型采用深蓝灰工作台、国内与海外双链路、就地修复入口。

已实现概览、Mullvad/Windscribe 设置向导、网关表单校验、Clash YAML 与对应 DNS 扩展下载、脱敏配置预览、演示检测与启停、自动启动偏好、诊断情境切换和脱敏诊断下载。

**状态与启停均为演示。** 原型不执行 PowerShell、不检测实际 VPN、不启动辅助程序、不修改系统代理或 Windows 启动项。偏好与输入仅保留在页面内存中，刷新即清除。配置下载会在本机生成文件；Windscribe YAML 包含用户输入的网关凭据，需自行保管。

配置源快照来自上级仓库 `providers/`，测试检查分流规则、DNS、辅助节点、Mullvad 接口绑定及 Windscribe 防回环规则保持一致。修改上级模板后，应同步 `src/templates/` 并运行测试。导入配置后仍需在 Clash Verge 核对应用设置与 DNS 扩展绑定。

## 直连组件一体化交付约定

用户要求直连组件随助手提供。桌面安装包应附带独立子程序，普通用户不单独下载 helper，也不手填或复制程序路径。原型已按这一目标展示，但当前前端目录尚未打包或启动该二进制。

- 固定布局：助手可执行文件与 `components/direct-helper/mullvad-direct-helper.exe`、`components/direct-helper/direct.yaml` 一起交付；助手以自己的安装目录解析组件位置，不要求用户配置路径，不依赖从另一款软件的安装目录复制内核。
- 内核作为独立进程运行，只有它加入 VPN 排除项；主界面、Clash 内核和 Windscribe 主进程继续留在 VPN 内。不能将直连功能直接并入 GUI 进程后，把整个助手排除出 VPN。
- 助手负责校验、启停、故障提示和随包更新；运行数据放入当前用户应用数据目录。安装升级保持组件路径稳定；组件缺失或损坏进入“修复安装”，不引导用户寻找或单独下载 exe。
- Mullvad 通过官方 CLI 自动定位并添加排除项；Windscribe 首次排除项仍按受支持能力引导用户在官方客户端确认，组件位置由助手提供。只有实际设置和链路验证通过，才显示配置完成。
- 旧版已有运行实例、排除项和启动项先识别，再由向导迁移；避免同时运行两份 helper 或遗留旧路径。保留历史可执行文件名，迁移不依赖改名。
- 正式发布包携带所用内核版本的许可证和对应源码信息。

开发：`npm install`、`npm run dev -- --host 127.0.0.1 --port 4173 --strictPort`。

验证：`npm test`、`npm run build`。视觉验证与交互记录见 `design-qa.md`。

上述桌面接入已在 [desktop](../desktop/README.md) 实现为 0.1.0 预览版。本目录保留设计与浏览器演示，不代表真实运行状态。根目录现有脚本仍是旧版可用方案，其行为没有因前端原型而改变。
